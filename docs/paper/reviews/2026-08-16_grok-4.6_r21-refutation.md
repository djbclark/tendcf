## 1. The third-arrow argument is unsound

The load-bearing step is here:

> The third arrow settles it — "trust entries → the agent's own config" cannot be projector output, because the projector writes exactly one file and that is not it. At least one arrow therefore already describes where a thing ends up *in the running system* rather than which container the projector emits. Arrow two reads the same way.

`docs/architecture/projector-reconciliation-2026-08-16.md:157-164`

**Premise stands. Inference does not.**

Arrow 3 is not a `host_specific.json` container. That is fixed by the same sentence that defines the projector:

> The projector's target is `$(sys.workdir)/data/host_specific.json` and nothing else

`docs/architecture/architecture-DEFINITIVE-v3.md:441-442`

and by the schema’s exclusive read path:

> The validator and agent read their own configuration ONLY from here

`schema/goal-file.schema.json:232` (same claim at `goal-file-schema-reconciliation-2026-08-15.md:393-395`)

I tried two ways to make all three arrows projector output. Both fail as corpus-consistent readings:

- **“Agent” means cf-agent, “config” means `host_specific.json`.** Fable’s source line is `trust entries → the validator's own config` (`goal-file-schema-opinion-fable.md:395-396`). The decided text swapped “validator” for “agent”; the schema pairs those two words as tendcf-agent, not cf-agent. The 16 Aug document itself treats the destination as a *different, still-unspecified file* (`projector-reconciliation-2026-08-16.md:304-306`). Gemini’s wrap is the only mapping that would make this reading true, and it was rejected.
- **The post-approval derivation has two sinks, so arrow 3 is still “projector output.”** That redefines “the projector” against `v3.md:441-442`. It is a possible English reading of the parenthetical *in isolation*. It is not available once the one-file constraint is granted — and R21.1 grants that constraint.

So: arrow 3 is not projector-output structure. Granted.

What follows is only: **the list is not uniformly a projector-container spec.** That is compatible with four hypotheses: system-level dataflow (R21.1), a mixed list, drafting residue, or an over-constrained sentence. R21.1 picks one and treats the others as closed.

The form is affirming the consequent:

- If the chain is dataflow, some arrows need not be projector output.
- Some arrows are not projector output.
- Therefore the chain is dataflow.

The source audit that fed this adjudication already used the weaker verb: “If arrow three is not projector output, arrow two **need not** be either.” §3 upgrades that to “Arrow two **reads the same way**” (`:162`). Possibility is not identity. That is the defect.

It is also a fallacy of composition. Arrow 1 is output-shaped (`entries → the generic bundle's containers` — this is what P-2 implements). Arrow 3 is not. A heterogeneous list does not become uniformly dataflow because one member is. Once heterogeneity is admitted, arrow 2’s genre is not inherited from either neighbour.

**Special pleading inside the same document.** §1 uses arrow 3 as a *binding output constraint*:

> the decided mapping routes trust entries *away* from the projection

`projector-reconciliation-2026-08-16.md:81-85`

§3 uses the same arrow as proof the chain is *not* an output spec (`:157-160`). Those roles can be forced together (“dataflow destinations constrain emission”), but then the theory is applied asymmetrically: arrow 3’s destination *binds* the projector (don’t emit trust); arrow 2’s destination *excuses* the projector from emitting the named lists (the bundle will grow them later). The extra hop is given only to the arrow that otherwise kills P-3.

**Provenance cuts against R21.1, not for it.** The parenthetical is compressed Fable:

> entries → `nix2cf_services`-style containers, tombstones → the negative-promise lists **the generic bundle iterates**, trust entries → the validator's own config

`goal-file-schema-opinion-fable.md:393-396`

“Iterates” names an *input* the bundle walks, not a list the bundle renders at eval. The 15 Aug reconciliation dropped that phrase when it copied the sketch into decided text (`goal-file-schema-reconciliation-2026-08-15.md:527-529`; same words at `architecture-DEFINITIVE-v3.md:455-457`). R21.1 does not recover a meaning the decided text always had. It inverts the dropped qualifier.

## 2. R21.1 proves too much

The solvent is: when an R21 clause pinches, reread it as a different layer.

Applied once, it demotes the parenthetical. The same move applies to the tripwire in the same sentence:

> any change that inspects entry *values* to decide output *structure* is the interpreter returning

`architecture-DEFINITIVE-v3.md:457-459`

“Output *structure*” can be shifted to system-level promise shape (start vs stop) just as “negative-promise lists” was shifted to eval-time `.cf`. Then a projector that splits on `state` has not tripped anything: the *system* structure is what changed, and that is policy’s job. That is exactly the reading R21.1 needs to be unable to license.

§3 says the tripwire “keeps full force as a mechanical test (see N-1)” (`:168-169`). N-1 is **new** text (`:246`). It is a fence built this evening, not a property of the dataflow reading. A later editor can say: R21.1 established that R21’s structural vocabulary is system-level; N-1 was a P-3 implementation choice; amend N-1. The reading taught them how.

The register entry — the residue as filed — has no arrows at all:

> Projector discipline: policy-free by discipline, not construction; value-inspecting structure decisions are the interpreter returning.

`goal-file-schema-reconciliation-2026-08-15.md:1233`

If arrows may be dataflow, arrow 1 dissolves too: “entries → the generic bundle's containers” becomes the vacuous end-state “entries end up in containers.” P-1 and P-2 treat it as a mapping constraint. The document needs the arrows to be output spec on Monday and dataflow on Tuesday.

“By discipline, not construction” (`:1233`, `:1193-1195`) is an honesty clause that the guarantee is not a theorem. It is not a licence to reread inconvenient clauses into a different layer.

## 3. Stronger reading: the parenthetical is elevated sketch, and the override should have been filed

Of the four rejected alternatives, **drafting-residue plus an explicit amendment** is stronger than R21.1. The design is not over-constrained. The *text* is over-specified.

Why residue, not dataflow:

- Provenance is a sketch. Fable’s containers were `nix2cf_services`-style (`goal-file-schema-opinion-fable.md:393-394`). That vocabulary was later marked preview-channel and corrected as C-9 (`goal-file-schema-reconciliation-2026-08-15.md:1118-1125`; `docs/paper/tendcf-architecture-guide.md:840-842`). The arrow list travelled with it into decided prose without the “ILLUSTRATIVE” stamp §16.A got.
- The filed residue is the tripwire, not the arrows (`:1233`).
- Three cold readers treated arrow 2 as a projector-container claim they were entitled to refuse (`projector-opinion-gemini.md:28`; `projector-opinion-grok.md:70`; `projector-opinion-cursor.md:64`). None recovered “dataflow.” A clarification that no competent reader sees is a rewrite.

The other three alternatives are weaker, and I will say why so this is not a preference:

| Alternative | Why it loses to residue+amend |
|---|---|
| Tripwire scopes to *changes*, not baseline | Grammatically available (`any projector change`, `:530-532`; v3’s bare `any change`, `:457`). Makes R21 a grandfather clause. The register states the prohibition without “change” (`:1233`). N-1 would be unauthorized. This is the solvent in another costume. |
| `state` is a type discriminator, not a value | Same move P-1 already makes for kind (`projector-reconciliation-2026-08-16.md:75-80`): closed enum, schema-fixed. But P-1’s own test is *position* — “never read from an entry body.” `state` *is* an entry-body field (`schema/goal-file.schema.json:67`; the 15 Aug sketch at `:615`). The discriminator reading also licenses filters on `coverage` and `writer`, which no opinion wanted. |
| Design genuinely over-constrained | Only if both halves bind *as projector-output spec*. They don’t have to. P-3 + tripwire + C-4 are consistent the moment the parenthetical is retired. Calling that “over-constraint” mistakes a drafting collision for a design collision. |

R21.1 is the cheapest *process* (no words change). Residue+amend is the cheapest *reading* (the register already states R21 without arrows; C-9 is the house precedent for demoting this exact sketch family). Cheap process with a bad inference is how quiet overrides happen.

## 4. “Clarification, not an amendment” is not honest

Same section, both claims:

> A 3-0 refusal of **decided text** is not something to wave through

`projector-reconciliation-2026-08-16.md:145-147`

> This is a **clarification of R21, not an amendment** — **no decided text changes**

`:167-168`

If the refused reading was never the meaning, the opinions did not refuse decided text — they refused a misreading, and “3-0 refusal of decided text” is false. If they refused decided text, the operative meaning changed and “no decided text changes” is false. That is internal inconsistency, not taste.

What changed, in force if not in glyphs: before tonight, a reader of `v3.md:455-457` / `reconciliation:527-529` could take arrow 2 as a projector-container obligation. After R21.1, that reading is closed and the tripwire-plus-P-3 reading is mandatory. The words sit still. The obligation moved.

§15 is the house form for that move:

> where this document corrects `e1-adjudication-xhigh-2026-08-15.md`, the corrections register in §15 is the authority and E1 stands elsewhere.

`goal-file-schema-reconciliation-2026-08-15.md:7-8`

> E1 remains the binding verdict; these amend it where it is wrong or under-specified. C-1, C-4, and C-7 are errors; the rest are letter-level amendments or completions.

`:1076-1078`

C-4 is the relevant model: it says “corrected as written” (`:1094-1098`) when prior binding text could not be kept. C-9 did the same to the guide’s Augments illustration (`:1118-1125`).

R21 is not E1, so this does not belong *inside* 15.1 as a correction of E1. It belongs in the **same genre**: a numbered C-n in the 16 Aug document (or a 15.3 targeting 15 Aug §9 / v3 §9) that says the second arrow, read as a projector-container spec, is withdrawn, and that the tripwire and C-4 still stand. Filing it as residue R21.1 (“so the next reader does not re-derive it,” `:170`) puts an override in the costs register so it never has to admit it is an override.

If nothing changed, a new residue id is unexplained. Residue ids carry new costs or new decisions. They are not how one records “what yesterday’s sentence always meant.”

## 5. P-3 survives. R21.1 is not load-bearing for the mapping.

P-3 does not fall with R21.1. It is independently forced:

1. **C-4.** The tombstone persists in the goal file; “the negative promise renders from the **file**”; the projector is a function of the new goal file alone (`goal-file-schema-reconciliation-2026-08-15.md:336-340`). Same claim in the schema (`schema/goal-file.schema.json:67`) and in v3 (`architecture-DEFINITIVE-v3.md:730-735`).
2. **R4 if omitted.** Extra-entry detection reports and does not remove. A comprehensive domain with no projected tombstone has no actuated removal path — “R4 reborn” (`:347-355`, `:354`). §3 already recites this *after* the R21.1 paragraph (`projector-reconciliation-2026-08-16.md:172-177`).
3. **Briefing honesty.** “stops being managed; the thing REMAINS” vs “will be stopped and unloaded” (`:343-345`; v3 `:736-739`) is a lie if the mutation engine cannot see the tombstone.
4. **3-0 on the mapping, for these reasons**, not for the dataflow reading. Gemini, Grok, and Cursor each keep tombstones in-kind and treat a split list as the tripwire.

What falls if R21.1 is withdrawn: only the claim that R21 *already said* P-3. The decided mapping does not move. The tripwire stays, and is cleaner, if the parenthetical is retired rather than layer-shifted.
